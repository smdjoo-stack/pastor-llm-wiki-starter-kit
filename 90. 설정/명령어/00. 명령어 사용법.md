# 명령어 사용법

이 볼트의 `/수집` 같은 표현은 실제로 등록된 명령입니다. 어떤 도구를 쓰느냐에 따라 진입점이 다릅니다.

| 도구 | 진입점 |
|---|---|
| Claude Code | `.claude/commands/*.md` — 터미널에 `/`로 자동완성 |
| Codex (GPT) | `.agents/skills/*/SKILL.md` — 레포 로컬 스킬, `AGENTS.md`를 함께 읽음 |
| Antigravity | `.agents/workflows/*.md` — 채팅에서 `/이름`으로 실행 |

세 진입점 모두 이 폴더(`90. 설정/명령어/`)의 정의 파일을 가리키는 얇은 포인터이며, 실제 실행 규칙은 여기 하나뿐입니다. 명령만 입력해도 되지만 대상과 원하는 결과를 함께 말하면 더 정확합니다.

## 전체 명령 목록

| 명령 | 하는 일 |
|---|---|
| `/수집` | **`00. 수집함` 전체**를 원본자료로 보존하고 설교위키 생성 — 인박스를 비운다 |
| `/위키` | **지정한 폴더나 파일**만 원본자료로 보존하고 설교위키 생성 — 하는 일은 `/수집`과 같고 대상만 다르다 |
| `/주석` | 성경 본문 AI 리서치를 설교준비 참고자료로 만듦 (Wiki 추출 안 함) |
| `/주석설정` | `/주석`의 리서치 깊이·범위 레시피 조정 |
| `/설교연결` | 1차설교를 분석해 연결자료 생성 (초안은 수정 안 함) |
| `/설교완성` | 확정 설교를 완성설교로 보존, Wiki/MOC 갱신 |
| `/질문` | 특정 설교와 무관하게 설교위키에 자유 질문을 던져 답을 찾음 |
| `/활용` | 완성설교를 파생 콘텐츠로 변환 |
| `/활용설정` | 출력 레시피 조정 |
| `/상태` | 볼트 현황 스냅샷 (읽기 전용) |
| `/점검` | 월간 점검표 항목 자동 점검 (기본 읽기 전용) |

## 좋은 요청 예시

```text
/수집
00. 수집함/책에 오늘 넣은 파일만 처리해 줘.
원본은 보존하고 새 Wiki를 만들기 전에 중복부터 확인해 줘.
```

```text
/수집
수집함에 있는 거 전부 처리해 줘.
어느 폴더에 넣었든 상관없이, 읽어보고 맞는 원본자료 폴더로 보내 줘.
```

```text
/위키
10. 원본자료에서 상태가 미처리인 것만 위키로 만들어 줘.
원본은 옮기지 말고 그 자리에 두고.
```

```text
/설교연결
2026-09-13 두려워하지 말라.md를 대상으로 해 줘.
핵심 질문은 “두려움 가운데 하나님은 어떻게 공동체를 주시는가?”야.
```

```text
/질문
두려움과 믿음의 관계에 대해 내가 만든 위키가 뭐라고 하는지 찾아줘.
```

## 공통 실행 방식

1. AI는 `LLM-운영지침.md`와 해당 명령 파일을 읽습니다.
2. 대상이 모호하면 파일 목록을 보여주고 짧게 확인합니다.
3. 기존 파일을 검색하고 새 파일·수정 파일 계획을 알립니다.
4. 작업 후 생성·수정·보류·확인 필요 항목을 보고합니다.
5. 파일을 실제로 만들거나 고친 명령(`/상태`, `/점검` 제외)은 `log.md`에 한 줄을 추가하고, 필요하면 `index.md`도 갱신합니다.
6. `index.md`의 통계·설교 흐름·MOC 목록이 바뀌면 같은 값으로 `90. 설정/대시보드.html`의 `DATA` 블록도 함께 갱신합니다 (두 파일은 항상 같은 시점의 스냅샷이어야 합니다). 개수를 셀 때는 `.gitkeep`, 파일명에 "안내"가 들어간 문서, `종류`/`상태`가 "예시"인 파일을 제외합니다.

사용자가 `미리보기만` 또는 `파일은 수정하지 마`라고 하면 제안만 하고 변경하지 않습니다.

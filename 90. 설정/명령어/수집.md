# /수집

## 목적

**`00. 수집함`에 있는 것을 전부 처리한다** — `10. 원본자료`로 보존하고, 다시 쓸 지식을 `20. 설교위키`로 만든 뒤 MOC에 연결한다. 단순 요약으로 끝내지 않는다.

한 문장으로: **원본자료로 보내고, 설교위키를 만든다.**

## `/위키`와의 관계 — 하는 일은 같고 대상이 다르다

| 명령 | 대상 | 쓰는 때 |
|---|---|---|
| **`/수집`** | **`00. 수집함` 전체** (대상을 말하지 않아도 된다) | **인박스를 비울 때** |
| **`/위키`** | **사용자가 지정한 폴더나 파일** | **특정 자료만 골라 위키로 만들 때** |

**둘 다 원본자료로 보존하고 설교위키를 만든다.** 이 문서의 「실행」부터 「완료 보고」까지가 **두 명령의 공통 절차**이며, `/위키`는 대상 지정 방식만 다르다(`90. 설정/명령어/위키.md`).

차이가 하나 더 있다 — **`/수집`은 자료를 수집함 밖으로 옮기므로 수집함이 비워진다.** `/위키`의 대상이 이미 `10. 원본자료`에 있으면 **이동 없이** `상태: 미처리` → `처리완료`만 바뀐다.

## 인박스 원칙 (2026-09-12 신설)

`00. 수집함`은 **인박스**다. 넣는 사람은 분류하지 않는다.

- **수집함의 하위 폴더는 구속력이 없다.** 넣는 사람의 편의를 위한 칸일 뿐이고, 최종 분류는 **자료를 읽은 뒤 이 명령이 정한다.**
- **`10. 원본자료`의 하위 폴더가 실제 분류다.** 수집함에서 어느 칸에 있었든, 내용을 읽고 맞는 폴더로 보낸다. 옮겼으면 **왜 옮겼는지 원본 노트에 적는다.**
- **자료의 주인이 누구든 이 명령 하나로 처리한다.** 목회자 본인의 과거 원고든 외부 저자의 자료든 절차는 같다. 다른 것은 `저자_발행자`에 누구 이름을 적느냐뿐이다(아래 「저자 표기」).

> [!warning] 이전 구조와 달라진 점
> 2026-09-12 이전에는 `00. 수집함/기존자료`에 들어온 자료를 `/등록`이라는 **별도 명령**이 처리했다.
> 그 구조는 **아직 아무도 읽지 않은 시점의 폴더 선택이 어느 명령을 실행할지 결정**했기 때문에,
> 외부 자료가 `기존자료`에 들어오면 매번 사람이 발견해 수동으로 우회해야 했다
> (실제 사례: `10. 원본자료/기사와자료/2025-05-23 당신은 정말 성경을 믿습니까.md` — 2026-09-10 재분류).
> **판정을 폴더에서 내용으로 옮기기 위해 두 명령을 `/수집` 하나로 합쳤다.** 이후 "수집함 밖의
> 특정 경로만 처리하는" 자리는 `/위키`가 맡는다. `/등록`이라는 이름은 **2026-09-12에 폐지되었다.**

## 입력

- `00. 수집함`의 **모든 하위 폴더** (기사와자료 · 떠오른생각 · 블로그 · 유튜브 · 책 · 기존자료)
- 대상을 따로 말하지 않으면 수집함 전체를 훑고 **처리할 파일 목록을 먼저 사용자에게 확인한다**
- 선택 사항: 이번에 관심 있는 질문, 주제, 본문

> 수집함 **밖**의 특정 파일·폴더를 처리하려면 `/위키`를 쓴다. 이미 `10. 원본자료`에 있으나
> `상태: 미처리`로 남은 자료도 `/위키`의 대상이다.

## 실행 — `/위키`도 이 절차를 따른다

> 아래 「실행」부터 「완료 보고」까지는 **`/수집`과 `/위키`의 공통 절차**다.
> `/위키`는 1번의 대상 범위만 다르다(수집함 전체가 아니라 지정한 경로).

1. **자료를 읽는다.** 어느 폴더에 있었는지는 참고만 한다.
2. **자료유형을 판정한다** — `책` / `유튜브` / `팟캐스트` / `블로그` / `SNS` / `기사와자료` / `강연` / `설교` / `강의` / `성경공부` / `교육자료` / `기타`. 모호하면 사용자에게 묻는다.
3. **저자를 판정한다** — 아래 「저자 표기」를 따른다. 판정 **근거를 원본 노트에 적는다.**
4. **보낼 폴더를 정한다** — 2·3번의 결과로 `10. 원본자료`의 하위 폴더를 고른다. 수집함에 있던 칸과 달라도 된다. 다르면 그 이유를 원본 노트 `## 출처 정보`에 적는다.
5. **같은 원본이 이미 `10. 원본자료`에 있는지 확인한다.** 제목·본문·발행일·share URL로 대조한다. 같은 자료의 다른 판본(개요본/원고본, 같은 설교의 다른 자리)이면 **병합하지 말고 각각 보존한 뒤 상호 링크**하고, 판단 근거를 적는다.
6. **원문을 내용 변경 없이 옮긴다.** 이동 여부가 불분명하면 복사를 우선하고 사용자에게 알린다. `90. 설정/템플릿/원본자료 템플릿.md`의 프론트매터(`종류`/`자료유형`/`제목`/`저자_발행자`/`출처_URL`/`발행일`/`확인일`/`상태`/`태그`)를 씌운다 — 수집함에 있던 원문은 프론트매터가 없어도 되지만, `10. 원본자료`로 넘어가는 순간부터는 이 형식을 갖춰야 한다.
7. **프론트매터 값을 가능한 범위에서 채운다.** 날짜 형식과 `상태` 값은 `90. 설정/사용안내/07. 속성 작성 규칙.md`를 따른다(`상태: 미처리` → Wiki 추출을 마치면 `처리완료`). **본문의 원문 내용 자체는 손대지 않는다.** 논지가 있는 자료(책·강연·설교·논문 등)는 `## 논지 요약`의 핵심 주장·주요 논거를 채운다 — 원문을 대체하지 않는 별도 섹션이다.
8. **자료를 다시 쓸 수 있는 작은 단위로 읽는다.** 중심 메시지와 핵심 질문을 뽑는다(설교면 목회적 질문, 강의·성경공부면 핵심 가르침·주제).
9. **기존 Wiki와 제목·동의어·내용 중복을 검색한다.**
10. **새 Wiki를 만들거나 기존 Wiki에 근거 있는 내용을 덧붙인다.** 전체 자료를 Wiki 한 편으로 복제하지 않는다. Wiki 프론트매터의 `출처` 배열에 6번에서 보존한 원본 노트 위키링크를 큰따옴표로 감싸 넣는다(`07. 속성 작성 규칙` 11번). 기존 Wiki에 덧붙일 때는 배열에 더한다.
11. **관련 MOC가 있으면 연결한다.** 없고 자료가 아직 적으면 새 MOC를 만들지 않는다.
12. **원본 노트에 생성·수정한 Wiki의 링크를 남긴다.** 원문 자체는 변경하지 않고 `## 처리 기록`만 추가한다 — 원본↔Wiki 양방향 링크가 완성된다.

## 저자 표기 — 자료의 주인에 따라 달라지는 유일한 규칙

**내 것이 아니면 원창작자의 이름을 쓴다.** (2026-09-10 목회자 지침)

| 판정 | `저자_발행자` | 함께 할 일 |
|---|---|---|
| **본인** | 목회자 이름(`07. 속성 작성 규칙` 14-1) | 판정 근거를 적는다 (1인칭 목회 화법, 본인 이력 진술 등) |
| **외부** | **원창작자 이름** | 원출처(URL·저작명)를 찾아 적는다. 못 찾으면 `검증/출처미확인` |
| **혼합** | 누가 어느 부분인지 함께 적는다 | 예: `{목회자}(앞부분 묵상 초안) · {외부 저자}(뒷부분 인용·전사)` |
| **미확정** | `미정` | `검증/출처미확인` + `> [!question] 확인 필요` + 추적 단서 |

- **AI는 저자가 아니다.** ChatGPT·Claude로 번역·요약·정리한 것일 뿐이면 **AI가 아니라 원창작자의 이름을 쓴다.**
- **추측해서 채우지 않는다.** 근거가 없으면 `미정`으로 두고 추적 단서를 남긴다(`07. 속성 작성 규칙` 14번).
- **`미확정`은 외부로 취급한다.** 실패 방향이 비대칭이기 때문이다 — 외부를 본인으로 착각하면 원창작자 이름이 사라지지만, 본인을 외부로 착각하면 불필요한 검증 태그가 붙을 뿐이고 목회자가 떼면 된다.
- **원출처 대조 전에는 강단에서 원저자 표시 없이 인용하지 않는다.**

## 자료의 성격을 구분한다 — 모든 자료에 적용

**책·유튜브·블로그·기사는 물론 목회자 본인의 원고에도 사실과 의견이 섞여 있다.** 원본자료 노트에 옮길 때 다음을 구분한다.

| 구분 | 무엇인가 | 볼트에서의 처리 |
|---|---|---|
| **사실** | 확인 가능한 사건·연구결과·통계·데이터 | 대조하지 못했으면 `검증/사실미대조` |
| **주장** | 저자·발표자가 제시하는 주장 | 저자 이름과 함께 적는다. 사실처럼 쓰지 않는다 |
| **해석** | 저자가 사실을 해석한 방식 | 주장과 구분해 적는다 |
| **예화** | 설명을 위해 쓴 이야기·사례 | `25. 예화`로 뽑을 수 있다 |
| **나의 해석** | 이 자료를 설교에 어떻게 쓸지에 대한 생각 | `> [!note] 해석 제안`으로 표시 |

> [!warning] 상충하는 정보
> **저자의 주장이나 유튜버의 의견을 객관적 사실처럼 쓰지 않는다.** 책 한 권을 요약했다는
> 것만으로 그 주장이 검증된 것이 되지는 않는다. 특히 자기계발서·유튜브 영상의 통계와
> 연구 인용은 원출처가 부실한 경우가 많다 — `검증/사실미대조`를 붙이고 추적 단서를 남긴다.
>
> **이것은 목회자 본인의 원고에도 그대로 적용된다.** 내 원고라는 사실이 그 안에 인용된
> 통계·연구·타인의 말을 검증해 주지는 않는다.

## 추출 후보

성경본문, 설교주제, 성경인물, 신학, 예화, 인용문, 묵상과통찰, 설교아이디어. 모든 후보를 억지로 만들지 말고 재사용 가치가 있는 것만 만든다.

**Wiki로 뽑을 때의 기준**(원칙 2 — 모든 것을 쪼개지 않는다). 아래에 해당할 때만 독립 노트로 만든다.

- 다른 설교에서도 **반복해서** 쓸 수 있다
- 여러 자료와 연결될 수 있다
- 하나의 **명확한 주장이나 논리**를 가진다
- 좋은 예화로 다시 쓸 수 있다
- 특정 주제를 이해하는 **핵심 개념**이다

해당하지 않으면 **원본자료 노트 안에 그대로 둔다.** 원본은 출처를 보존하고, Wiki는 설교에서 쓸 생각을 보존한다.

## 성경본문 Wiki의 연결 필드 (`07. 속성 작성 규칙` 6-1번)

`성경본문` Wiki를 만들거나 갱신하면 `관련본문`·`관련주제`·`관련인물`·`관련신학`·`관련예화`·`관련인용`·`관련통찰` 배열을 채운다. 본문(body)의 `## 관련 주제·인물·신학`·`## 관련 통찰과 예화` 절에 적은 링크를 그대로 올리면 된다 — 본문 링크는 사람이 읽는 설명이고 배열은 기계가 집계하는 색인이라 **둘 다 남긴다.** 실제로 존재하는 노트만 넣고, MOC·설교아이디어·원본자료 링크는 넣지 않는다.

## 태그 (`07. 속성 작성 규칙` 13번)

만들거나 갱신하는 모든 노트의 `태그`를 통제 어휘로 채운다. 자유 주제어는 쓰지 않는다.

- `본문/{정식 책 이름}/{장}` — 예: `본문/요한복음/15장`, `본문/시편/63편`. 절은 넣지 않는다. 줄임말 금지. **설교주제·성경인물·신학은 상한이 없다**(허브 노트라 계속 자라는 것이 정상). **그 밖은 6개**(규칙 13-1). 상한 대신 근거 규칙이 품질을 지킨다 — **장을 붙이려면 그 장이 노트 본문에 실제로 인용돼 있어야 한다.** 근거가 없으면 장을 떼고 책 단위로 둔다.
- `용도/{상황}` — 장례·결혼·심방·새가족·다음세대·가정·재정·직장·공동체·수련회 중 **그 상황에서 실제로 꺼내 쓸 수 있을 때만**. 단어가 나온다고 붙이지 않는다.
- `절기/{표준값}` — 7번의 표준값에 해당할 때만.
- `검증/원어미대조` · `검증/사실미대조` · `검증/출처미확인` · `검증/날짜미상` · `검증/제목미확정` · `검증/원고미완성`
  — 본문에 `> [!question] 확인 필요` 콜아웃을 남겼으면 **그에 대응하는 검증 태그를 반드시 함께 붙인다.**
  콜아웃만 있고 태그가 없으면 나중에 검색되지 않는다.
- `상충` — `> [!warning] 상충하는 정보` 콜아웃을 남겼으면 붙인다.

기존 노트를 갱신할 때는 **태그를 덮어쓰지 말고 없는 것만 더한다.** `검증/*`과 `상충`은
AI가 스스로 지우지 않는다 — 목회자가 확인한 뒤에만 지운다.

## 주의

- **저자의 표현을 임의로 교정하거나 신학적 입장을 바꾸지 않는다.** 목회자 본인의 원고든 외부 저자의 글이든 같다 — `10. 원본자료`는 덮어쓰거나 축약하지 않는다는 절대 원칙이 전체에 적용된다.
- 자료에서 사용된 직접 인용은 **원출처가 확인되지 않아도 인용문 Wiki로 만든다** — 단 아래 세 가지를 반드시 함께 남긴다(2026-09-10 목회자 결정으로 완화된 규칙, `07. 속성 작성 규칙` 15번).
  1. `검증/출처미확인` 태그와 `> [!question] 확인 필요` 콜아웃
  2. `> [!note] 해석 제안 — 추적 단서` 콜아웃에 **어디를 찾아보면 되는지**(저작명·강해 번호·판본·검색어 등). 단서가 전혀 없으면 "단서 없음"이라고 명시한다
  3. `## 출처`의 `자료명`에 미확인 사실을 적고, 빈칸으로 두지 않는다
  **이것은 "확인했다"는 뜻이 아니라 "목회자가 확인할 목록에 올린다"는 뜻이다.** 원출처 대조 전에는 강단에서 원저자 표시 없이 인용하지 않는다.
- **없는 인용을 지어내는 것은 여전히 금지다.** 위 완화는 *원고에 실재하는 인용*을 노트로 만드는 문제에만 적용된다. 원고에 없는 문장을 인용처럼 만들거나, 인용자를 추측해서 채우지 않는다.
- 날짜, 본문, 자료 종류, 저자를 알 수 없으면 `확인 필요`로 표시하고 대응 `검증/*` 태그를 붙인다.
- 개인·상담 사례는 익명화하고 불필요한 세부 정보를 삭제한다.

  - **근거**: 기존 구조는 `00. 수집함`의 어느 폴더에 넣었느냐가 `/수집`과 `/등록` 중 어느 명령이 실행될지를 결정했다. 그런데 폴더는 **자료를 읽기 전에** 선택되고, 자료의 주인은 **읽은 뒤에야** 판정된다. 실제로 외부 설교(루이 기글리오)가 `기존자료`에 들어와 2026-09-10 수동 재분류가 필요했고, 같은 유형의 자료가 재차 들어왔다.
  - **`00. 수집함/수집함 안내.md`가 자기모순이었다** — "분류에 오래 고민하지 말고 가장 가까운 폴더에 넣습니다"라고 해 놓고, 그 분류 하나가 명령을 갈랐다.
  - **두 명령의 규칙 차이가 실제로는 저자 표기 하나뿐이었다.** "표현을 교정하지 않는다"는 `10. 원본자료` 절대 원칙에 이미 있었고, "사실·주장·해석 구분"은 본인 원고 안의 인용에도 필요하며, 인용문 완화 규칙은 `07. 속성 작성 규칙` 15번의 보편 규칙이다. 자료의 주인에 진짜로 달린 것은 **누구 이름을 저자로 적고 강단에서 출처를 밝힐 의무가 생기는가**뿐이다.
  - **모델**: `00. 수집함`은 인박스다 — 넣을 때 분류하지 않고, 분류는 처리하면서 나온다.

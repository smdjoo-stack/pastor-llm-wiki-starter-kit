# /점검

## 목적

`90. 설정/사용안내/06. 월간 점검표.md`의 항목을 사용자를 대신해 훑어보고 우선순위와 함께 보고한다. 기본은 읽기 전용 — 사용자가 명시적으로 "고쳐줘"라고 하지 않으면 파일을 수정하지 않는다.

## 입력

없음. 필요하면 점검 범위를 좁히는 지시(예: "설교위키만", "이번 달 수집함만").

## 실행

`90. 설정/사용안내/06. 월간 점검표.md`의 각 항목을 확인한다.

1. **오래 남은 수집함 파일**: `00. 수집함`에서 오래된 파일을 찾는다.
2. **원본 없는 Wiki**: 프론트매터 `출처` 배열이 비어 있는 설교위키 노트를 찾는다 (`07. 속성 작성 규칙` 11번).
3. **중복 Wiki**: 제목이나 내용이 비슷한 노트가 여러 개 있는지 검색한다.
4. **출처 확인 필요**: `확인필요` 상태이거나 출처가 비어 있는 인용문·예화·묵상과통찰을 나열한다.
5. **MOC 연결 누락**: 어느 MOC에도 연결되지 않은 Wiki 노트(고아 노트)를 찾는다.
6. **길잡이 없는 MOC**: 링크만 나열되고 핵심 질문·길잡이 설명이 없는 MOC를 찾는다.
7. **재활용 안 된 완성설교 통찰**: 최근 완성설교 중 아직 Wiki에 반영되지 않은 것이 있는지 확인한다.
8. **활용 결과물의 역유입**: `20. 설교위키`에 `70. 설교활용` 콘텐츠가 잘못 들어간 것이 없는지 확인한다.
9. **출력 레시피 정합성**: 레시피가 실제 교회 형식과 다르다는 신호(사용자 피드백, 예시 불일치)가 있는지 확인한다.
10. **개인정보·민감 정보**: 실명 상담 사례나 개인정보가 남아 있는지 확인한다.
11. **검토 상태**: 프론트매터의 `검토: 미검토`로 오래 남아 있는 Wiki 노트를 나열한다.
12. **URL 자료의 원문 누락**: `자료유형`이 `유튜브`·`블로그`·`SNS`·`팟캐스트`인 원본자료 중 `## 원문 또는 원본 메모`에 발췌 없이 URL만 있는 것을 찾는다 — 링크가 사라지면 근거도 함께 사라진다.
13. **index/대시보드 동기화**: `index.md`의 통계·설교 흐름·MOC 목록과 `90. 설정/대시보드.html`의 `DATA` 값이 서로 다르면 표시한다. 개수 집계 시 `.gitkeep`, "안내" 문서, `종류`/`상태`가 "예시"인 파일은 항상 제외한다.

## 완료 보고

중요도순으로 정리한 목록을 보여준다. 각 항목에 다음을 포함한다.

- 무엇이 발견되었는가
- 관련 파일 `[[링크]]`
- 권장 조치 (사용자가 승인하면 그때 수정)

사용자가 "고쳐줘" 또는 특정 항목의 수정을 명시적으로 요청한 경우에만 파일을 수정하고, 수정 후 `log.md`에 `## [YYYY-MM-DD] /점검 | {요약}` 항목을 추가한다.
